# 玄决移动端界面重设计 — 调研报告与执行提示词

> 交付物定位：前半部分是调研结论（现状诊断 + F1 参考页手法解剖 + 可迁移清单），后半部分是据此撰写的、供后续执行直接使用的《玄决移动端界面重设计提示词》。
> 调研范围：仓库根目录源码（`index.html` / `css/style.css` / `js/app.js` / `js/daliuren.js` / `js/lunar.js`）、`webapp/` 桌面端、`test_dom.mjs`、`build.mjs`、`capacitor.config.json`、`img/`。
> 调研方式：静态代码盘点（行号与取值为实测，非估算）。本报告不含未经检索验证的外部论断。

## 1. 执行摘要

1. **现状诊断结论**：移动端"基本没有变化"的根因不在配色或材质，而在**信息层级的表达方式**——所有内容块共用同一个 `.card`（16px 圆角、16px 内边距、同一宽度、同一入场动画），层级只靠 `h3` 标题 + 3px 强调条区分；全屏最大字号是 30px 的页标题和 22px 的干支行，正文区间密集分布在 10–14px。结果是"每一块都一样大、一样重、一样近"，缺少视觉主角。
2. **F1 参考页的真实价值**不在于它长什么样，而在于它作为一份提示词的**规格化程度**：每个区块都给出精确字号/字距/行高、z-index 分层、动画时长与缓动、组件契约（含缩放数学）、逐字列出的资产地址。这种"可被无歧义执行"的写法，才是应该迁移的东西。
3. **可迁移手法共 10 项**（见 §4），其中与玄决内容天然同构的是：全幅背景 + 暗色蒙版、48–120px 展示级字号与 −0.05em 级字距、纵向渐隐的大数字、单一强调色克制使用、`backdrop-filter` + 竖向蒙版的底部过渡、`cubic-bezier(0.16,1,0.3,1)` 阶梯式入场、2200ms 三次缓出的数字滚动、玻璃卡配方。
4. **明确不迁移**：React/Vite/Tailwind 技术栈、外链 CDN 图片、F1 品牌资产与配色、"手机里再套手机"的展示框架、Dynamic Island 装饰。玄决是本地优先、零外链的 vanilla JS SPA，这三条红线不可破。
5. **项目内已存在更强先例**：`webapp/` 桌面端已经使用"单一陶土强调色 + 衬线展示字 + 发丝线行、去卡片化"的语言（`.now-meta` 无卡元信息行、25px 衬线判定、`.acts` 顶发丝线双栏、`.signals` 标签行）。移动端重设计应向这套语言收敛，而不是另起炉灶。
6. **硬约束清单**（见 §6）必须全绿：13 个页面渲染函数中首页/问事/盘面三处可重构；`computeDaliuren` / `plainLang` / `qiKe` 等占卜算法禁止改动；`test_dom.mjs` 的 60+ 条断言所依赖的 ID / class / 文案必须保留；构建链 `root → build:www → www/ → cap sync → gradlew assembleDebug` 不变；浅色/深色双主题 + `prefers-reduced-motion` 必须同时成立。

## 3. F1 参考页手法解剖

参考页本身的技术栈（React/Vite/Tailwind/外链图）与玄决无关，但它作为一份提示词的组织方式，有五个值得复制的结构特征：

1. **先钉技术栈与令牌**：字体族与权重、自定义色值、body 背景与 antialiased，全部前置声明，后续不再重复解释。
2. **分层写在明处**：背景图 `z-0` → 暗色蒙版 `z-[1]` → 内容 `z-[2]` → 浮层 `z-50`，每层的定位与尺寸一并给出。
3. **组件带契约**：`PhoneMockup` 给出外框圆角 `clamp()`、内屏圆角、Dynamic Island 几何、以及"内容按 390px 基准渲染、`scale = screenW/390`、`transform-origin: top-left`"的缩放数学。
4. **每个屏一节、逐元素列规格**：字号、字距（−0.05em 至 −0.08em）、行高（0.72–0.95）、z-index、动画名与延迟（300/500/700/800/1000/1200ms）全部可抄。
5. **动画给完整关键帧**：`fadeSlideUp`、`scaleIn`、`speedReveal`（含 `skewX` 与 `blur` 中间态）、`fadeSlideLeft` 均写出 0%/60%/100% 与 `both` 填充模式；数字滚动给出缓动函数（三次缓出）、时长（2200ms）与启动条件（延迟后 `requestAnimationFrame`）。

这三条是"能被执行"与"只能被想象"的分界：**精确的几何、精确的时序、精确的资产**。

## 5. 项目内先例：桌面端已经走在对的方向上

`webapp/css/app.css` 的语言比移动端更接近目标态，可作为移动端改写的直接参照：

- 单一强调色 `--clay:#BE5E3B`（移动端对应 `--accent:#D97757` / `--primary:#B25B38`）；
- `.now-meta` 用**一行元信息流**替代卡片；
- `.verdict` 25px 衬线作为结论主角；
- `.acts` 双栏 + 顶部发丝线，不用边框盒子；
- `.signals` 用 64px 标签列 + 值行，标签与值通过排版分层而非容器分层；
- `.tend` 用语义色胶囊但只出现一次。

移动端重设计 = 把这套"去卡片化、单一主角、发丝线分层"的语言，按手机单列竖排的约束重新编排。

# 附：《玄决移动端界面重设计提示词》（执行用）

## A. 技术栈与令牌（前置声明，后文不再解释）

- 栈：vanilla JS SPA（`index.html` + `css/style.css` + `js/app.js` 字符串模板），**不引入** React/Vite/Tailwind/外部字体/外部图片。
- 字体：`--serif` = Noto Serif SC 栈（展示字专用）；`--sans` = 系统栈（正文）。
- 现有令牌继续生效：`--bg:#1F1E1D`、`--card:#262624`、`--ink:#F5F4EE`、`--ink2:#C2BFB8`、`--muted:#8F8B81`、`--accent:#D97757`、`--accent-3:#B25B38`、`--primary:#B25B38`、`--on-primary:#FFF6F1`、`--green:#43A67E`、`--red:#E5615B`、`--warn:#E0A45E`、`--blue:#A9B4BE`、`--glass-blend`、`--glass-blur`、`--glass-line`、`--glass-in`、`--serif`、`--sans`、`--ease-out`。浅色主题由 `[data-theme="light"]` 覆盖，**新增令牌必须同时给浅色值**。

```css
@keyframes revealUp{from{opacity:0;transform:translateY(24px)}to{opacity:1;transform:none}}
@keyframes revealScale{from{opacity:0;transform:scale(.94)}to{opacity:1;transform:none}}
@keyframes displayReveal{0%{opacity:0;transform:translateY(10px);filter:blur(6px)}100%{opacity:1;transform:none;filter:blur(0)}}
@keyframes hairlineGrow{from{transform:scaleX(0)}to{transform:scaleX(1)}}
```

- `revealUp` / `revealScale` / `displayReveal` 用于区块与主角入场，配 `.d1`–`.d8` 形成 100ms 步进阶梯。
- `hairlineGrow` 用于 `.hair` 首行的发丝线自左展开（`.5s`，`transform-origin:left`）。
- 数字滚动：新增 `countUp(el,to,{delay,duration:2200})`，缓动 `t=>1-Math.pow(1-t,3)`，`requestAnimationFrame` 驱动，`delay` 后启动；目标元素需带 `font-variant-numeric:tabular-nums`。**不改变任何 DOM 结构语义**。

## 7. 结论

移动端"没有变化"是**层级表达手段单一**造成的，而非材质或配色陈旧。F1 参考页提供的可迁移资产是一套规格化写法：全幅背景 + 蒙版分层、展示级字号与紧字距、渐隐大数字、单一强调色、底部模糊过渡、阶梯式入场与数字滚动。把这套写法映射到玄决自身的内容结构（时课 hero / 一课倾向主角 / 六法门横轨 / 三传大字号 / 发丝线宜忌），配合桌面端已验证的"去卡片化"语言，即可在不触碰占卜算法、不破坏测试契约、不引入外部依赖的前提下，完成一次可见的界面代际更替。执行提示词见附章，按 §E 顺序推进。
