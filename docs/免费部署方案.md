# 玄决云同步 · 免费部署方案

这篇回答四个问题：

1. **有没有免费域名？** —— 有，托管平台白送二级域名 + 自动 HTTPS 证书，不用买。见第 0 节。
2. **能不能直接在你机器上当服务器？** —— 不要这么干，原因在下面第 1 节，而且不是配置问题。
3. **注册能不能完全免费？** —— 能，而且已经是了：账号就是一串你自己选的同步令牌，没有邮箱、没有手机号、没有短信验证码，服务端只存它的 SHA-256 哈希。**任何一家托管平台都不会向你要钱来"注册账号"**，花钱的只有机器和数据库，而这两个都有免费档。
4. **AI Key 我提供，怎么限流、怎么保护？** —— 服务端强制「每日 N 次 + 每分钟 M 次」，Key 加密落库或只放进程内存，接口永不返回明文。见第 4.2 节第 4 步和 `docs/后端方案.md` §10。

术语提醒：下面"账号"指的是托管平台（Render / Neon 这些）的后台账号，不是游戏内的用户数据。

## 0. 先说结论

**免费域名有，而且不用买。** 托管平台白送一个二级域名 + 自动 HTTPS 证书：

| 平台 | 白送域名 | 证书 |
|---|---|---|
| Render | `https://xxx.onrender.com` | Let's Encrypt 自动签发、自动续期 |
| Koyeb | `https://xxx.koyeb.app` | 同上 |
| Fly.io | `https://xxx.fly.dev` | 同上 |
| Neon | `https://ep-xxx.neon.tech` | 同上 |

**注意**：这些域名属于平台，不属于你。平台政策变化时域名可能失效，用户侧改一次服务器地址即可（App 里就是改一个字符串）。真要自己的域名，也可以免费：`eu.org` / `freedns` 提供免费顶级/二级域，再绑到 Render 上即可 —— 但这是可选项，不是必需品。

**能不能用你这台电脑当服务器？** —— 见下面第 1 节，结论是不要这么干。

## 1. 为什么不用你这台机器当服务器

先说结论，再说依据。

你现在这台机器：

- 内网地址 `10.21.121.155/12`，是 NAT 后的内网 IP，**没有公网 IP**；
- 到 `api.ipify.org` 的出网探测失败，说明出口没有可用的公网映射。

服务端要能被手机端的 App 访问，必须满足任一条件：有公网 IP、或在公网路由器上做端口映射、或用内网穿透。三者都不具备，所以**这台机器只能当客户端，不能当服务端**。这不是"改个配置"能解决的，是网络拓扑决定的。

顺带说一句：就算硬穿透出去也不该这么干。玄决的口碑建立在"本地优先、隐私优先"上，把用户加密备份存在一台家宽、动态 IP、没有 SLA 的机器上，是对用户不负责。

**替代方案**：下面第 3 节在托管平台上跑，机器在别人的机房里，有公网域名和自动签发的 HTTPS 证书，你的机器完全不用参与。

## 2. 账号模式：已经做到"完全免费注册"

纯令牌账号模式，`js/cloud.js` 和服务端都已实现并测试通过（后端 27 项、前端 11 项断言全绿）：

| 环节 | 做法 | 为什么免费 |
|---|---|---|
| 注册 | 用户自选或生成一串 16–64 位令牌（`[A-Za-z0-9._-]`） | 没有邮箱验证，没有短信，没有 OAuth 回调 |
| 服务端存储 | 只存 `SHA-256(token)` + 前 6 位前缀 | 服务端永远不知道令牌明文，也就无从拿去登录 |
| 找回 | 令牌前 6 位 + 恢复口令 → 服务端返回 `recovery_blob` | 不依赖邮件/短信投递 |
| 成本 | 注册没有任何第三方服务调用 | **零边际成本，注册功能永久免费** |

加密模型（服务端零知识）：

```
令牌 ──PBKDF2──▶ 数据密钥 ──AES-256-GCM──▶ 密文（上传）
恢复口令 ──PBKDF2──▶ 包裹密钥 ──AES-GCM──▶ recovery_blob（上传）
```

服务端只存密文，连"有什么类型的数据"都看不到（密文长度除外）。找回能真正解出数据，因为 `recovery_blob` 里包的就是数据密钥本身。

**唯一需要用户承担的成本**：托管平台的机器和数据库。下面第 3 节。

## 3. 免费平台怎么选（这是本篇最关键的决策）

### 3.1 先看体检表（2026 年 10 月核对过的公开额度）

| 平台 | 免费 Web 服务 | 免费数据库 | 会删数据吗 |  |  |
|---|---|---|---|---|---|
| **Neon + Render** | Render：512MB / 0.1 CPU / 空闲 15 分钟休眠 | Neon：1GB 存储、100 CU 时/月 | **不会删**，只是空闲 5 分钟后挂起计算 |  |  |
| **Neon + Koyeb** | Koyeb：512MB / 0.1 vCPU / 2GB / 100GB 出站 | Neon：同上 | **不会删** |  |  |
| Fly.io | 3 台共享 256MB 小机 | 机载 Postgres 3GB 卷 | 不会删 |  |  |
| Render 全家桶 | 512MB / 0.1 CPU / 空闲休眠 | **免费库 30 天后过期删除** | **会删** |  |  |
| Koyeb 全家桶 | 512MB / 0.1 vCPU | **免费库 90 天后过期** | **会删** |  |  |

### 3.2 结论：数据库用 Neon，Web 服务用 Render

理由只有一条，但它是否决性的：

> **Render 免费的 PostgreSQL 在创建 30 天后过期并被删除，宽限期 14 天。Koyeb 免费库 90 天后过期。**

对一个"云端备份"产品来说，这意味着用户 30 天前的加密备份会被平台静默清空，而他还以为自己的数据在云端。产品定位和免费档限制直接冲突，所以不能把数据库放在 Render 或 Koyeb 上。

Neon 免费档的休眠机制不一样：它不会删数据，只是把计算挂起（scale to zero），下次请求几百毫秒到几秒内自动恢复。用户的加密密文一直在存储里。

两点代价，提前说清楚：

- Neon 免费档 1GB 存储。玄决密文很小（案例/对话/生辰/重点，GCM 后通常几十到几百 KB），1GB 能装几千个用户，个人用绰绰有余，但**不是无限容量**。
- Neon 免费档每月 100 CU 时。挂起时不消耗，正常同步请求几百毫秒到几秒，用量极小。这个额度只在大规模拉取时才可能触及。

### 3.3 组合方案（推荐）

```
用户 App ──HTTPS──▶ Render 免费 Web 服务（xuanjue-server）
                          │
                          └──TLS──▶ Neon 免费 PostgreSQL
```

- Render 负责接请求，跑 Fastify；
- Neon 负责存数据，不被删；
- 两边都不需要信用卡；
- HTTPS 由 Render 自动签发 Let's Encrypt 证书。

如果 Render 后台没有免费档名额（地区性），把 Web 服务换成 Koyeb（免费档不需要信用卡，512MB / 0.1 vCPU / 100GB 出站，区域只支持法兰克福和华盛顿）。**数据库仍然用 Neon**，别换成 Koyeb 自带库。

## 4. 具体步骤

### 4.1 建数据库（Neon，约 3 分钟）

1. 打开 <https://neon.tech>，用 GitHub 或邮箱注册，**不需要信用卡**。
2. 新建 Project，区域选离你近的（`Singapore` 或 `Tokyo`），Postgres 版本默认。
3. 在 Project 详情里复制连接串，形如：
   `postgresql://user:password@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
4. 确认串尾有 `?sslmode=require`。**这是托管库连接失败最常见的原因**，Neon 强制 TLS，而本地 `pg` 驱动默认不启用 SSL。
5. 建库后执行 schema（二选一）：
   - 本地执行：`cd server && DATABASE_URL='刚才那条串' npm run db:init`
   - 或在 Render 后台的 Shell 里执行同一命令

`npm run db:init` 走的是 `scripts/db-init.mjs`，用 pg 驱动以 simple query 协议整段发送 `schema.sql`。**不需要 psql 客户端** —— 托管平台的原生 Node 环境通常不带它，这是原 `package.json` 里 `psql "$DATABASE_URL" -f schema.sql` 跑不通的原因。

### 4.2 部署 Web 服务（Render，约 5 分钟）

仓库根目录已有 `render.yaml`，Render 会自动识别，但**环境变量必须在后台填**：

1. <https://dashboard.render.com> → New → Web Service，连接这个 GitHub 仓库。
2. Render 读**仓库根**的 `render.yaml`（Blueprints 只认仓库根目录，`server/render.yaml` 是旧版残留、不会被读取）。其中 `buildCommand: npm install --prefix server`、`startCommand: cd server && node scripts/db-init.mjs && node index.js`、健康检查 `/health` 都已配好。
   - **注意这里没有 `rootDir`**：Render 规定「服务根目录之外的文件，构建期与运行期都不可用」。App 前端产物 `www/` 在仓库根，一旦设 `rootDir: server` 就看不到它，`/app` 会 404。所以服务根必须是仓库根，`www/` 随仓库入库直接可用，云端也不需要重建前端。
3. 在 Environment 里补必需三项：
   - `JWT_SECRET`：本地生成 `openssl rand -base64 48`，**别用短串**
   - `DATABASE_URL`：第 4.1 步那条 Neon 连接串
   - `CORS_ORIGINS`：`https://localhost`（Capacitor 打包出的 App 源就是这个）
4. **AI 云代理（可选，强烈推荐配）** —— 配了它，用户端就「零配置」能提问，你统一管限额：

   ```bash
   openssl rand -base64 32      # → AI_KEY_MASTER（Key 加密主密钥，只放环境变量）
   ```

   | 变量 | 作用 | 建议值 |
   |---|---|---|
   | `AI_PROXY_ENABLED` | 云代理总开关 | `true` |
   | `AI_KEY_MASTER` | 加密用户自带 Key 的主密钥，32 字节 | `openssl rand -base64 32` |
   | `AI_SITE_KEY` | **站长内置 Key**，配了用户才真正零配置 | 见下方格式 |
   | `AI_DAILY_LIMIT` | 每用户每天提问上限（成本护栏） | `30` |
   | `AI_RATE_PER_MINUTE` | 每用户每分钟上限（防突发） | `6` |

   `AI_SITE_KEY` 格式是 `协议://Key@BaseUrl/模型名`，多把 Key 用 `|` 分隔自动轮询：

   ```bash
   AI_SITE_KEY=openai://sk-xxx@https://api.deepseek.com/v1/deepseek-chat
   AI_SITE_KEY=openai://sk-a@https://api.deepseek.com/v1/deepseek-chat|openai://sk-b@https://api.deepseek.com/v1/deepseek-chat
   ```

   **不配 `AI_SITE_KEY` 也能开代理**：此时走「用户在 App 里填 Key，Key 加密落库」的老路，服务端仍然代理转发 + 限额。两者可以同时存在，内置 Key 优先。

5. Deploy。等它给出 `https://xxx.onrender.com`。

改 CORS 时注意：多域名用逗号分隔，**不要用 `*`**。`preflight.mjs` 会检查这一项，用了 `*` 时任何网站都能调你的后端。

### 4.3 自检

本地先跑（推荐，能在 30 秒内定位问题）：

```bash
cd server
npm run local-check     # 建 schema → 起服务 → 注册/解锁/同步/拉取/找回/注销 全链路
```

用将要上线的环境变量再跑一遍：

```bash
DATABASE_URL='...' JWT_SECRET='...' CORS_ORIGINS='https://localhost' npm run preflight
```

它检查 `JWT_SECRET` 长度、`DATABASE_URL` 协议与 sslmode、**CORS 是否含 `https://localhost`**、数据表齐全性、`users` 表是否为令牌模式、`pgcrypto` 扩展。任何一项不过，退出码非 0，并给出改法。

上线后验证：

```bash
npm run ping -- https://xxx.onrender.com
```

### 4.4 在 App 里填地址

App 端：**我的 → 云同步 → 设置服务器地址**，填 `https://xxx.onrender.com`（**不要带尾斜杠**，SDK 会自己规整；也**不要带 `/v1`**，SDK 自己拼路径）。

地址只存在本机 `localStorage`，不随数据上传。然后：

- 第一次用：**创建同步令牌（免费）** → 抄下令牌和恢复口令 → 开启同步；
- 换设备：**使用已有令牌登录**；
- 令牌丢了：**用恢复口令找回**（填令牌前 6 位 + 恢复口令）。

## 5. 必须提前告知用户的限制

诚实比好用重要。这些是免费档的客观限制：

| 限制 | 用户会感觉到 | 怎么办 |
|---|---|---|
| Render 空闲 15 分钟休眠 | 手动"立即同步"时偶发卡 1 分钟 | 已在 UI 提示"同步中…"；需要秒开就升级到 $7/月 |
| Neon 空闲 5 分钟挂起计算 | 冷请求慢几百毫秒到几秒 | 数据不丢；自动恢复 |
| Neon 免费 1GB | 理论容量上限 | 几千个普通用户够用；超了升级 |
| Neon 每月 100 CU 时 | 极端重度拉取可能触顶 | 挂起不计费；用满后当月只读 |
| HTTPS | 必须有，否则密文裸奔 | Render 自动签发，无需操作 |

本地调试想用 `http://127.0.0.1:8787` 的话，需要在 Android 侧放开明文流量（`android:usesCleartextTraffic="true"` 仅限 debug）。**正式包不要开** —— 明文会把密文和令牌打到网关上。当前 `capacitor.config.json` 的 `androidScheme: https` 和默认网络安全策略正好挡住了这条风险路径，保持现状。

## 6. 常见问题

**Q：Neon 免费档会不会也有一天删数据？**
按 Neon 官方文档，免费档只挂起计算、不删数据，超配额时报错但保留。存储是连续计量不按周期清零。政策可能变，所以第 3 节给了可替换路径：数据库换成 Fly.io 的 3GB 持久卷，或升级 Neon 付费档。

**Q：能不能完全 0 成本跑，一个平台都不花钱？**
能，就是上面这套。两台机器都不要信用卡。所谓"花钱"只在超出免费额度或需要免冷启动时发生。

**Q：为什么不用 GitHub Pages 之类托管前端？**
本项目的 Web 资产（`www/`）已经打进 APK 本地运行（`webDir: www` + `androidScheme: https`），不依赖远端托管。云同步只需要服务端 API，Free 档足够。

**Q：服务端日志会不会泄密？**
`index.js` 里的 req serializer 只记 `method / url / ip`。body（含令牌、恢复口令、密文）和 Authorization 头一律不记。`db-init.mjs` 打印连接串时会把密码替换成 `***`。

**Q：配了云代理，用户的提问内容你会看到吗？**
会。这是云代理的固有代价：请求要经服务端转发给模型服务商，服务端必然看得到明文。

所以设计上做了三层约束：

1. **不落库**：提问内容只在内存里过一手，不写 `ai_usage` 之外的任何表（`ai_usage` 只记 `user_id + 日期 + 次数`）；
2. **不打日志**：AI 路由不记 body，错误只回归类错误码，上游原文不透传；
3. **不留 Key**：明文 Key 只在 env（进程内存）或 AES-256-GCM 密文里，接口永不返回明文。

如果连"服务端过一手"都不能接受，把 `AI_PROXY_ENABLED` 设为 `false`，走用户自带 Key 直连 —— 那条路服务端只见到密文同步数据，完全不知道用户问了什么。客户端会自动降级，UI 也会提示用户填自己的 Key。

**Q：云代理会不会把我的 Key 额度打爆？**
两道闸：`AI_DAILY_LIMIT`（默认 30 次/人/天）和 `AI_RATE_PER_MINUTE`（默认 6 次/人/分钟），都是服务端强制，客户端绕不过去。 Neon 免费库 + 30 次/天，几百个用户也就一天几千次，个人 Key 完全扛得住。
